# Trace v4.9 Lifecycle Closure + Attribution Noise Reduction Design

Trace v4.8 release validation showed that the provenance layer now records useful semantic facts, but several records still mislead offline attribution:

- Missing skill loads can remain open until trace finalization, then appear as successful `skill.load` records.
- Final answers still produce non-factual claims such as headings and closing sentences.
- Claim source locations can be polluted by Markdown fragments such as `**Entry**: \`src/pricing.mjs`.
- Response claims still carry broad legacy refs in the same primary source field used for direct evidence.
- Compaction records preserve large artifacts, but do not expose before/after/summary provenance refs as first-class fields.

## Goals

1. Close tool and skill lifecycle records with accurate error status and metadata.
2. Keep final response claims limited to attribution-worthy factual statements.
3. Make `direct_evidence_refs` minimal and move broad inherited refs into `legacy_context_refs`.
4. Add explicit compaction provenance refs for before context, serialized input, summary output, retained/dropped refs, and after/continue context.
5. Reduce viewer noise by making background/title LLM turns and duplicated schema artifacts visually secondary.

## Non-Goals

- Do not implement root-cause diagnosis or blame assignment.
- Do not remove raw events, artifacts, or legacy fields required for replay.
- Do not change benchmark runner behavior or provider configuration.

## Design

### Skill And Tool Lifecycle Closure

When a `tool.call` span named `skill` ends with an error, the corresponding formal `tool.call` record must become `status: "error"` and include:

- `error`
- `output`
- `skill_name`
- `request_status: "missing" | "error"`
- `quality_flags: ["skill_request_unresolved"]`

The associated `skill.load` record must be closed instead of finalized as running. It should use `status: "error"` for missing or failed loads, and include `available_skill_names` when the error text contains that list. Health should count it in `skill_request_unresolved`, not in unexpected missing close records.

### Claim Classifier And Source Location Hygiene

`splitResponseClaims` should drop lines that are only headings, framing, or non-factual postamble, including:

- `Summary`, `Here's the summary`, `总结`
- `No further steps needed`
- Markdown section headings without factual content

Claim source extraction should ignore Markdown-decorated path fragments and only accept paths that look like clean file paths, URI paths, or known source spans. A claim may still keep no source location when its source path cannot be parsed cleanly.

### Claim Evidence Narrowing

Each response claim should separate refs into:

- `direct_evidence_refs`: minimal matched evidence facts.
- `legacy_context_refs`: original broad refs inherited from the response segment.
- `context_refs`: context records only.
- `execution_refs`: tool/change/verification refs relevant to the claim.

For test-result claims, verification facts and verification refs should be preferred over code facts. For change/fix claims, change refs should be preferred over generic evidence facts when available. `source_refs` on the claim node should be reconstructed from the narrowed refs plus legacy context refs, while attribution consumers should read `direct_evidence_refs` first.

### Compaction Provenance

`context.compaction` records should promote these top-level data fields:

- `algorithm`
- `before_context_refs`
- `after_context_refs`
- `serialized_tail_artifact_ref`
- `summary_artifact_ref`
- `retained_message_ids`
- `dropped_message_ids`
- `retained_fact_refs`
- `dropped_fact_refs`
- `token_estimate_before`
- `token_estimate_after`
- `auto_continue_prompt_ref`

The existing `context_ledger` remains, but these fields give offline attribution a stable, shallow contract.

### Viewer Noise Reduction

The HTML viewer should retain all records but visually mark background/title turns and duplicated schema artifacts:

- Add a background/title count in Trace Health.
- Add labels for `agent_role: "title"` and `is_background`.
- Show artifact occurrence count where available.
- Keep the raw records accessible.

## Acceptance Criteria

- Trace version is `4.9`.
- Missing `repo-audit` skill attempts produce closed error records and `skill_request_unresolved > 0`.
- Final answer claim extraction excludes headings and non-factual postamble.
- Markdown path fragments are not emitted as malformed source locations.
- Claim records expose `legacy_context_refs`.
- Compaction records expose the shallow provenance fields listed above.
- Existing v4.x trace bundle files remain generated.
- Typecheck passes.
