# Trace v4.4 Lifecycle + Provenance Design

## Background

Trace v4.3 already records prompt assembly, context transforms, compaction, LLM calls, tool/MCP/skill calls, subagents, decisions, response output, artifacts, and dataflow edges. Real DeepSeek runs showed the next bottleneck is not lack of events, but weak lifecycle closure and weak evidence provenance:

- Some `llm.call` records remain `running` after cancellation or background work, so offline attribution cannot reliably tell whether a model turn completed, was cancelled, or was background noise.
- Subagent records capture delegated input but do not consistently expose returned output, child trace refs, and parent-child return edges.
- Compaction records include algorithm and retained/dropped messages, but token estimates and auto-continue provenance are incomplete.
- Final answers and decisions do not consistently reference concrete facts from tool/MCP/skill/subagent outputs.
- Viewer output mixes main chain, background title turns, compaction, raw records, and repeated artifacts too evenly.

## Goal

Trace v4.4 must make a case trace suitable as input for a separate offline root-cause attribution module without embedding diagnosis logic in opencode itself.

## Non-Goals

- Do not perform automatic root-cause diagnosis in trace generation.
- Do not remove existing major fields required by older consumers.
- Do not split `trace.html` into another HTML entry point.
- Do not make raw stream deltas part of the formal provenance records.

## Data Model Changes

### Trace Version

Set `TRACE_VERSION` to `4.4`.

### Formal Record Types

Add:

- `llm.turn`
- `agent.lifecycle`
- `exit.gate`
- `evidence.fact`

Keep existing `llm.call`, `loop.decision`, `response.output`, and other v4.3 records for compatibility.

### LLM Turn

`llm.turn` is a semantic lifecycle view over a provider stream. It records:

- `turn_id`
- `session_id`
- `parent_session_id`
- `message_id`
- `agent`
- `agent_role`: `main | subagent | compaction | title | background`
- `provider_id`
- `model_id`
- `span_id`
- `input_context_refs`
- `prompt_transform_refs`
- `tool_schema_ref`
- `request_id`
- `status`
- `duration_ms`
- `finish_reason`
- `stop_reason`
- `token_usage`
- `is_background`
- `metadata`

`llm.call` remains the span-level record. `llm.turn` is the normalized semantic record offline attribution should prefer.

### Agent Lifecycle And Exit Gate

Add `agent.lifecycle` for major loop milestones:

- `turn.started`
- `tool.selected`
- `tool.completed`
- `response.completed`
- `compaction.required`
- `auto_continue.started`
- `turn.completed`
- `turn.cancelled`

Add `exit.gate` for non-interactive run termination decisions:

- `has_final_answer`
- `needs_compaction`
- `auto_continue`
- `synthetic_continue`
- `continuation_source`: `user | compaction | system | none`
- `decision`: `continue | exit | wait | cancel`
- `reason`
- `message_id`
- `session_id`

The exit gate is observational: it records the decision and inputs. It should not invent a diagnosis.

### Compaction Provenance

Extend `context.compaction` ledger with:

- `algorithm`
- `token_estimate_before`
- `token_estimate_after`
- `context_limit`
- `reserved_output_tokens`
- `retained_message_ids`
- `dropped_message_ids`
- `retained_fact_refs`
- `dropped_fact_refs`
- `summary_artifact_id`
- `auto_continue_prompt_ref`
- `quality_flags`

Quality flags are structural facts such as `missing_token_estimate`, `empty_dropped_message_ids`, `summary_artifact_missing`, or `auto_continue_enabled`.

### Subagent Provenance

Enhance `subagent.call` with:

- parent session/message
- child session/message
- delegated prompt artifact/ref
- child trace ref when available
- child final response ref when available
- returned output artifact/ref
- status, duration, error

Add stronger edges:

- parent prompt/session `delegated_to` child session
- child final output `returned_to` parent task span
- child output `reported_to` parent response/observation

### Evidence Facts

Add `evidence.fact` records extracted from high-value observations:

- tool read/grep/list output
- verification output
- MCP tool output
- skill load output
- subagent output

Each fact records:

- `fact_id`
- `source`
- `category`
- `summary`
- `data`
- `source_refs`
- `source_locations`
- `confidence`: `observed | inferred`
- `metadata`

The implementation should be conservative. It should not try to deeply understand all content, only expose stable semantic facts and source refs.

### Dataflow Relations

Prefer strong semantic relations in new edges:

- `called`
- `returned_to`
- `delegated_to`
- `reported_to`
- `supported_response`
- `used_as_context`
- `transformed_to`

Legacy relation migration remains in place.

## Viewer Changes

`trace.html` remains the only HTML entry point. It should add or emphasize:

- Main Chain: user request, prompt assembly, main LLM turns, selected tools, final response.
- LLM Turns: grouped by role, with title/background collapsed.
- Context And Compaction: context transforms, compaction ledger, quality flags, artifacts.
- Subagents: parent-child graph, delegated prompt, child return.
- Evidence Facts: facts, source refs, source locations, consumers.
- Raw Events: still accessible, but stream deltas and large artifacts are not the default focus.

## Testing

Unit and integration tests should verify:

- Trace version is `4.4`.
- New formal record types are accepted.
- `llm.turn` is written and includes token usage when available.
- `exit.gate` records continuation/exit decisions.
- `context.compaction` includes quality flags.
- `subagent.call` closes with returned output when available.
- `evidence.fact` records link to observations and response output.
- `trace.html` contains the new sections and no `viewer.html` is emitted.

## Acceptance Criteria

- Existing v4.3 tests are updated to v4.4 without losing compatibility fields.
- Real runs produce formal records for LLM lifecycle, exit gate, compaction provenance, subagent return, and evidence facts.
- Raw stream deltas remain out of formal provenance records.
- `trace.html` is still the only HTML entry point.
- Typecheck passes.
