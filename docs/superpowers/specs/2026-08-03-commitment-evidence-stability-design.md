# Commitment Evidence and Candidate Stability Design

## Observed failure

On the same immutable Sphinx FeatureBench Bundle, the v10 process contract
produced structured lifecycle assessments but still classified the recorded
statement `I'll write the missing methods` as no commitment. A separate model
run also moved `dec167` below the fixed 24-candidate navigation boundary.

## Design

1. Project exact first-person forward-action language from recorded or verified
   hydrated candidate evidence into `candidate_commitment_cues`.
2. Keep the projection explicitly non-verdict-bearing. The Judge must classify
   every supplied cue as commitment, non-commitment, or ambiguous and explain
   its decision with candidate-local evidence.
3. Join that semantic decision with the bounded post-candidate trajectory to
   distinguish fulfilled work, responsible omission, and ordinary bounded
   investigation.
4. Raise the quality-first navigation page to 64 candidates. Existing global
   node, frontier, hypothesis, and request budgets remain authoritative.
5. Preserve independent root confirmation and all publication gates. Neither
   lexical projection nor navigation can publish a root by itself.
6. Treat mutation and verification counters as authoritative fulfillment
   facts. A commitment cannot be marked fulfilled when the bounded trajectory
   records no delivery.
7. Use recorded commitment cues only to prioritize the heavy Judge queue; cue
   priority is retrieval scheduling and remains non-verdict-bearing.
8. When a validated process defect has no offered predecessor, semantic repair
   receives the exact root-confirmation action contract instead of a generic
   list of legal endings.

## Safety

All new data is reconstructed offline from immutable Trace evidence. It is not
fed back to the observed Agent and does not modify its prompts, tool calls, or
repository actions.

## Acceptance

- A 40-candidate progress window judges all 40 candidates.
- Exact implementation language appears as a grounded, auditable cue.
- A process judgment cannot silently mark a supplied cue not applicable.
- Ordinary non-process attribution remains schema-compatible.
- The same Sphinx Bundle retains `dec47`, `dec167`, `dec236`, and `dec238` and
  explicitly adjudicates the `dec236` commitment lifecycle.
