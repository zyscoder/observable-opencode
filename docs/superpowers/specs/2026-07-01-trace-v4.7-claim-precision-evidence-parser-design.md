# Trace v4.7 Claim Precision And Evidence Parser Design

## 背景

Loop 1 的 v4.6 已经引入 `response.claim`、`structured_claim`、`context.compaction_check` 和 `Claim Evidence Matrix`。实测显示这些字段已经可用，但还存在四类影响离线归因质量的问题：

1. claim splitter 会把 `0.15`、`src/pricing.mjs`、`Math.min` 等代码/路径/小数拆断。
2. MCP 返回 JSON 时，部分 `evidence.fact` 仍退化为泛化 `fallback_summary`。
3. 文件读取证据仍偏路径级，缺少“discount cap = 15%”这类行级事实。
4. 每个 claim 继承整段 response 的全部 refs，导致过度归因。

v4.7 的目标是在不引入诊断逻辑的前提下，提高 trace 的事实粒度和 claim-证据匹配精度。

## 目标

1. 让 `response.claim` 切分保护代码片段、文件路径、函数名、小数和百分比。
2. 让 MCP JSON text 稳定生成非泛化 `structured_claim`。
3. 从常见 file/read/grep/snippet 输出中抽取行级事实。
4. 按 claim 文本和 evidence structured claim 做轻量匹配，减少每个 claim 继承全部 refs。
5. 让 `OPENCODE_TRACE_FORCE_COMPACTION=1` 在 trace 验证中稳定触发一次 compaction。
6. Trace Health 增加 precision 质量指标，暴露可供后续 loop 优化的问题。

## 非目标

1. 不做根因归因或诊断结论。
2. 不引入 LLM 作为 trace 后处理器。
3. 不删除 v4.6 字段。
4. 不把所有文件内容都解析为完整知识图谱，只做高价值模式抽取。

## 数据与语义变化

Trace version 升级为 `4.7`。

新增或强化质量标记：

```text
broken_claim_fragment
over_attributed_claim
generic_mcp_fact
path_only_evidence_fact
line_fact_extracted
deterministic_forced_compaction
```

`response.claim` 新增可选字段：

```ts
matched_evidence_refs?: string[]
match_strategy?: string
match_score?: number
```

这些字段只描述匹配事实，不表示诊断判断。

## Claim Splitter

采用 placeholder 保护策略：

1. 先保护 Markdown inline code：`` `src/pricing.mjs` ``、`` `0.15` ``、`` `Math.min` ``。
2. 保护裸文件路径：`src/pricing.mjs`、`docs/architecture.md:9`。
3. 保护小数、百分比和常见函数/属性表达式：`0.15`、`15%`、`Math.min`、`renewalQuote(input)`。
4. 再按段落、列表项、中文句号、英文句号、问号、感叹号、分号切分。
5. 最后恢复 placeholder，并合并明显断裂片段。

Trace Health 检测到 claim 以孤立反引号、孤立扩展名、小数半截、路径半截结尾时，标记 `broken_claim_fragment`。

## Evidence Parser

### MCP JSON

MCP 输出常见结构：

```json
{
  "content": [
    { "type": "text", "text": "{\"subject\":\"renewalQuote\",\"predicate\":\"owner\",\"value\":\"billing-platform\"}" }
  ]
}
```

v4.7 需要递归扫描 `data`、`output`、`content[]`、`typed_resources[]` 和 text JSON，优先抽取 `subject/predicate/value/path/line_start/line_end`。

### File Read / Grep

从 summary、snippet、text、output 中抽取高价值行级事实：

1. `owned by billing-platform` -> `owner = billing-platform`
2. `discount cap ... 15 percent` -> `discount_cap = 15%`
3. `entry point ... src/pricing.mjs` -> `implementation_entry = src/pricing.mjs`
4. `return "billing-platform"` -> `return_value = billing-platform`
5. `Math.min(..., 0.15)` -> `discount_cap = 0.15`

抽不到时保留现有 fallback，但加 `path_only_evidence_fact` 或 `generic_mcp_fact`。

## Claim-Evidence Matching

对每个 response claim：

1. 将 claim 文本归一化为关键词集合。
2. 将 evidence 的 `structured_claim.subject/predicate/value/source_span` 归一化为关键词集合。
3. 如果 claim 包含 evidence 的 value、subject 或 source path，则匹配。
4. matched evidence 优先进入 `direct_evidence_refs`。
5. 没有匹配时才回退到 response-level direct refs。
6. 如果 claim 仍继承超过 5 个 direct evidence refs，标记 `over_attributed_claim`。

## Deterministic Forced Compaction

`OPENCODE_TRACE_FORCE_COMPACTION=1` 应在 trace-enabled 会话中稳定触发一次 auto compaction。触发后在 trace 环境中写入 marker，避免同一 session 无限压缩。

实现约束：

1. 只在 `CaseTrace.isEnabled()` 为 true 时生效。
2. 只对非 summary 的 last finished assistant message 生效。
3. 每个 process/session 只触发一次。
4. `context.compaction_check.metadata.forced_overflow = true`。
5. 质量标记包含 `deterministic_forced_compaction`。

## Viewer

`Claim Evidence Matrix` 增加：

1. `matched_evidence_refs`
2. `match_strategy`
3. `match_score`
4. `quality_flags`

`Evidence Facts` 继续优先展示 `structured_claim`。

`Trace Health` 增加 precision 指标：

```text
broken_claim_fragments
over_attributed_claims
generic_mcp_facts
path_only_evidence_facts
```

## 成功标准

1. `trace_version` 为 `4.7`。
2. `0.15`、`src/pricing.mjs`、`Math.min` 不被拆成多个 claim。
3. MCP `repo_fact` JSON 能生成 `subject=renewalQuote`、`predicate=owner`、`value=billing-platform`。
4. architecture 文档能抽出 `discount_cap = 15%`。
5. claim matrix 中每条 claim 的 direct evidence refs 明显少于 v4.6 的全量继承。
6. forced compaction 不需要 `--continue` 也能在验证场景产生 `context.compaction`。
