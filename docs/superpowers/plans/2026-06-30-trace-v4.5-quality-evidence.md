# Trace v4.5 Quality Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Trace v4.5 quality and evidence provenance so trace output is structurally valid, lifecycle-complete, and easier for offline attribution to consume.

**Architecture:** Keep `trace.html` as the only visual entry point and keep existing v4.4 records compatible. Add trace quality metrics at provenance-summary time, refine evidence/source refs at write time, and expose quality issues in the viewer without doing root-cause diagnosis.

**Tech Stack:** TypeScript, opencode observability trace writer, Bun tests where available, `tsgo --noEmit` for local type verification.

## Global Constraints

- Do not add diagnosis/root-cause conclusions inside opencode.
- Do not restore or generate `viewer.html`.
- Preserve old fields where practical; add refined fields for new consumers.
- Do not promote stream deltas into formal records.
- Keep large text in artifacts and link by ref.
