# Trace v4.2 Viewer And Facts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Trace v4.2 with one HTML entry point, a clearer flow-style report, and stronger structured facts for offline attribution.

**Architecture:** Keep `CaseTrace` as the writer and `causal-trace-viewer.ts` as the report renderer. Update the formal trace contract in-place, remove the viewer alias output, enrich records before final summarization, and test the output bundle directly.

**Tech Stack:** TypeScript, Bun tests, existing opencode observability modules, static HTML/CSS.

## Global Constraints

- Do not add online diagnosis or automatic root-cause attribution.
- Generate `trace.html` only; do not generate `viewer.html` for new cases.
- Keep `trace.json` as the formal provenance trace.
- Keep `legacy-trace.json` as the old v1.3 summary.
- Do not inline large text into `trace.json`; use artifacts and previews.
- Do not write API keys or secrets to trace output.
