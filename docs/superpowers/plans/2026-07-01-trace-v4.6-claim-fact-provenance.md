# Trace v4.6 Claim-Fact Provenance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add claim-level provenance and structured evidence facts so trace output can support offline attribution without opencode performing diagnosis.

**Architecture:** Extend the existing v4.5 trace writer in place. Add `response.claim` and `context.compaction_check` records, enrich `evidence.fact` with `structured_claim`, refine Trace Health, and update the single `trace.html` viewer to show a claim-evidence matrix.

**Tech Stack:** TypeScript, opencode observability trace writer, static HTML renderer, Bun tests where available, `tsgo --noEmit` for local type verification.

## Global Constraints

- Do not add diagnosis/root-cause conclusions inside opencode.
- Do not restore or generate `viewer.html`.
- Keep large text in artifacts and link by ref.
- Do not promote stream deltas or token deltas into formal records.
- Preserve v4.5 fields where practical; add v4.6 fields for new consumers.
- `OPENCODE_TRACE_FORCE_COMPACTION=1` is a validation aid and must not change default production behavior.
