# Trace v4.1 Attribution Facts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Trace v4.1 as a cleaner semantic facts layer for offline root-cause attribution.

**Architecture:** Keep the current `CaseTrace` writer and provenance HTML viewer. Change the formal output contract, enrich component-specific records before summarization, and suppress weak observation records.

**Tech Stack:** TypeScript, Bun tests, existing opencode observability modules.

## Global Constraints

- Do not add online diagnosis or attribution conclusions.
- Do not inline large text into `trace.json`; use artifacts and previews.
- Preserve `trace.html` as the unified viewer and keep `viewer.html` as an alias.
- `trace.json` is the formal v4.1 provenance trace.
- `legacy-trace.json` is the old v1.3 summary.
- No API keys or secrets may be written to trace output.
